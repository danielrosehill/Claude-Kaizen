# Kaizen backlog

Atomic improvement units. Rules: `PRINCIPLES.md`. IDs are never reused; closed
items stay in the file with their final status.

Item format — keep it exactly, the Kaizen skills parse it:

```markdown
### K-NNN — <one-sentence title, no "and">
- status: open | in-progress | done | blocked | dropped
- priority: high | medium | low
- area: readability | structure | performance | tests | tooling | docs | dependencies | ux | accessibility | hardening | other
- source: baseline | P<NNN> | user <YYYY-MM-DD>
- depends-on: K-NNN, … | none
- scope: <files, modules or components it touches>
- why: <the improvement, in one or two sentences>
- verify: <command, test or observable check that proves it worked>
- behaviour-change: none | <what observably changes>
```
